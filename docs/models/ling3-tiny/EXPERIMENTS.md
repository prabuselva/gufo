| Query-projection export differs per artifact (GGUF header walk of both artifacts, 2026-10-18) | Measurement only; corrected a planning assumption. **Flash GGUF has no `bailingmoe3.attention.q_lora_rank` key** and ships the fused `blk.N.attn_q` (Q4_K [6144, 2560]); **Tiny ships the key = 256 plus the split `attn_q_a` (Q8_0 [256, 1536]), `attn_q_a_norm` (F32 [256]) and `attn_q_b` (Q8_0 [3072, 256]) with no fused `attn_q`**. First attempt keyed the split layout on the metadata value with an exact 256 match in both profiles → `ling3_flash.weights` on Flash failed `unsupported Ling 3.0 kernel geometry`. Decision: `q_lora_rank` parses as optional (default 0), profile carries `mla_q_lora` (Flash 0 / Tiny 256) + `mla_q_split`; split path in binder, CPU oracle, device decode (`Gemv`→`RmsNorm`→`Gemv`), batch decode (`GemvRows`→`RmsNormRows`→`GemvRows`) and WMMA prefill (extra `DenseF16Gemm` deferred behind kv_a/gate to reuse the single `pf_xh_` F16 stage). After the fix both artifacts bind and the oracle passes. |
| Tiny quant layout pins (`ling3_flash.weights` on the real file, 2026-10-18) | Tiny quantizes `blk.N.ssm_beta` and `attn_gate` Q8_0 (Flash: F32). Binder pin on ssm_beta relaxed from `{F32}` to the dense type set; every consumer (`Gemv`/`GemvRows`/`GemvGrouped`/oracle `MatVec`) is type-generic, and the WMMA dense-tier list never included it. |
| Tiny lacks SwiGLU clamp arrays (oracle segfault + fix, 2026-10-18) | gdb backtrace of the reference test on the Tiny file crashed at `ReferenceModel::Step` on `std::vector::operator[]`: `swiglu_clamp_exp/shexp` are `[num_layers_all]` on Flash but **absent on Tiny**, and Step/executor indexed them unconditionally (9 sites). Fix: bounds-safe `Config::ClampExp/ClampShexp` returning 0.0F when absent — 0 already means "no clamp" (`kClampEps` guard in `reference.cpp`, kernel limit checks). Tiny oracle then passes. |
| Tiny GPU enablement smoke + pp/tg (`gufo prompt` / `gufo bench`, Q8_0, exclusive, 2026-10-18) | End-to-end split-q device path works. Commands: `tools/bench/bench_bg.sh tinysmoke 300 build/release/gufo prompt --model …/Ling-3.0-tiny-Q8_0.gguf -p … -n 64 -t 0 -s 42` with `bench_wait.sh` watchdog; same pattern, `… bench … --n-prompt 2048 --n-gen 128`. |

| Prefill MLA v_b contracted over token rows instead of (token, head) slots (parity FAIL → fix → PASS, exclusive, 2026-10-18) | The first Tiny parity run failed exactly at MLA-block boundaries: prefill-through-17 logits worst relative **2.71** (PASS elsewhere; step/replay ≤0.0025). Root cause was a **production bug latent for Flash too**: `PrefillMla` staged the v_b GEMM input from `tokens * kv_rank` rows with `pf_rows_tok_` gather indices, but each head bucket reads the latent row of its own (token, head) slot. Tiny's geometry made the mis-gathered values large enough to flip logits at every MLA boundary; Flash prefill parity stays within tolerance at its shapes. Fix (`executor.cpp`): stage `tokens * heads * kv_rank` and gather with `pf_rows_slot_` for both index operands. Matched reruns: 17/39/40 logits 0.0506/0.1125/0.0477, hidden 0.0412/0.0450/0.0277, argmax all match, forward+quality rc=0. Commands: `bench_bg.sh tinyParity/parity2 900` running `ling3_flash_rocm_forward_test` + `ling3_flash_rocm_quality_test` with `GUFO_LING3_FLASH_GGUF` pointed at the Tiny file. |
| Serve constrained requests 400 in the reasoning state (marker empty) — shared bug, fixed and replay-verified (exclusive, 2026-10-18) | `gufo serve` + tools (or response_format) with thinking enabled failed every request on both Tiny and Flash with 400 `reasoning end marker is empty`: `ConstrainChatRequest` wrapped grammars via `JsonConstraint::WithReasoning(grammar)` whose default end marker is empty and throws (reached because both Ling runners report `kReasoning` when thinking is on; the gemma4 branch was the only one passing a marker). Fix in `text_model_runner.cpp`: pass the shared think-close marker (assembled from hex escapes) and skip wrapping when there is no grammar (native-dialect tool calls constrain nothing). `text_model_runner_test` PASS on cpu-test; tool-call replay 12/12 on both models — non-stream `finish_reason=tool_calls` + parsed arguments + followup from tool result, streamed id-then-name once + incremental argument deltas + framing containment both transports. Reports `/tmp/opencode/replay_report_{TINY,FLASH}.json`, driver logs `replay_driver_{TINY,FLASH}.out`. |
| `json_constraint_test` red since b996f776 — root cause, core fix, retuned expectations (cpu, 2026-10-18) | The final 4.6 sweep caught `json_constraint_test` aborting at its first `WithReasoning` assertion; the abort dates to the gemma4 reasoning/tool-grammar commit, which made the end marker mandatory (empty `end` threw) without updating this test. Two distinct defects surfaced. (1) Core: a corrected single-marker default is required by 15+ legacy call sites; the first attempt wrongly used an open+close concatenation, and a byte-trace probe against the linked library proved the free-form channel only completes when `end` is exactly the 8-char close token (`lt`+`/think`+`gt`, assembled from hex pieces). With that fallback, free-form reasoning, marker-partial bytes, quoted-header and answer-after-close cases all evaluate as specified. (2) Test: the native-tool reasoning expectations in `TestReasoningConstraint` predate the lexeme rewrite and asserted free text flowing straight into a native call with no close token. Measured acceptance matrices for both dialects and `required` on/off show the shipped language: bare call, close-token+call, and text+close-token+call are accepted; text+call without the close token is rejected, and a schema-invalid call stays rejected. Assertions were retuned to the measured language with the marker built from pieces, plus the sampler/mask cross-check prefixes retuned in kind — no engine semantics were changed beyond the default-marker restoration. `json_constraint_test` then passed, unblocking `ctest build/cpu-test` 131/131; `gpu-full -R ling3` passed 13/13 and tool-call replay re-passed 12/12 on Tiny and Flash against the rebuilt release binary. |
